## Scope clarification and hudfix decision

- P0 targets `NrFp8`, the fork's custom FP8 pass-in-one presets (local 18/19, sets 5/6; NVIDIA FP8 kernels + fork weights). It does not touch the runtime's built-in FP8 presets 1/2: A Legacy is the original FP8 network (`honest_tench`), B Small FP8 is the smaller/optimized one (`hnet-crazy-cuckoo-small-fp8`). Both are FP8; the reason they are unaffected is that they never enter `NrFp8`, not that they are non-FP8.
- Fork's HudFix is long-standing OptiScaler FG infrastructure (D3D11 27 KB, D3D12 34 KB, Vulkan 49 KB; 85 commits on that path), not a v0.10.0 feature. It derives a HUD-less image via resource tracking and feeds `DLSSG.HUDLess` for frame generation. Do not port wholesale.
- Corrected `docs/nvfp4-upstream-port.md`: it distinguished the historical 18-21 / set1-4 mapping from the current 18/19 -> set5/6 mapping (since `7ff8660`), said the schema exposes two FP8 choices, and recorded that P0/P1 affect only presets 18/19.
- Local already has a tag-driven HUD-less path: `HudTags` + `FgInput` + `HudComposerD3D12/Vk`, and `src/addon.cpp:3396-3452` runs Present NR on the HUD-less image, but only with DLSS FG active, `fg_present=BEFORE` (`early_confirmed`) and UI correction On; `DecideHudFrame` also requires `FrameGenerationReads`. To widen it to Present NR with FG off, first try relaxing those gates locally behind a hidden switch if the game still tags HUD-less/opacity; only games that never tag need HudFix-style synthesis. Prior XMX HUD-composition sweep also deferred for the same NR-stage mismatch (`docs/xmx-upstream-port.md:216-243`).
